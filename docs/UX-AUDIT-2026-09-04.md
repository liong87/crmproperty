# Lanthorn Properties CRM — UI/UX, design and Playwright audit

4 September 2026. All findings were confirmed by reading code and by driving a running
copy of the app in Chromium; nothing below is inferred.

## How it was tested

The app was never run against production. A source-only copy was stood up in an isolated
sandbox with its own PostgreSQL 16, `pnpm db:migrate`, `pnpm seed`, and an extra bulk
seed (80 leads, 29 properties, 23 contacts, 19 deals, 14 appointments, 1 project) so the
dense views had something to be dense with. Clerk was replaced by a sandbox-only auth
stub to allow role switching; that stub was **not** written back to the repo.

- **Modules reviewed:** Dashboard, Inbox, Working leads, Appointments (list + board),
  Pipeline, Leads (list, detail, new, edit, import, going-cold), Leads capture,
  Lead sources, Reports (+ Advertising spend), Properties, Projects, Contacts, Deals,
  Learning hub, Team, Templates, Users, Commission settings, More, User guide.
- **Roles tested:** `admin` (Aisyah) and `agent` (Nurul). Team-lead paths were reviewed
  in code (`ownershipFilter`, `visibleUserIds`) but not driven in the browser.
- **Viewports:** 1680×1000 desktop, 1366×800 laptop, 834×1112 tablet, 390×844 mobile.

## What was wrong, and what changed

### 1. Critical — silent failure and data loss risk

1. **Property, Project and Contact forms failed silently.** All three called `useForm`
   without reading `formState`, registered fields as `{ required: true }` with no
   message, and rendered no errors — so pressing Save on a blank Area did nothing at
   all: no message, no red field, no network call. Fixed in all three, with real
   messages, per-field errors, and a focused error summary. Verified in the browser.
2. **~38 form controls had no accessible name.** The local `Field` helper in the
   property and project forms rendered `<Label>` with no `htmlFor` and gave the child no
   `id`. Replaced by a shared `components/ui/field.tsx` whose render prop hands the
   control its `id`, `aria-invalid` and `aria-describedby`, so the wiring cannot be
   forgotten. Playwright now confirms 0 of 21 controls on the property form are unnamed.
3. **The Properties filter did nothing.** Four `<select>`s in a GET form with no submit
   button and no client JS: the only way to filter was pressing Enter in the search box.
   Added an explicit Apply, a Clear, and real labels for the four selects.
4. **Pagination silently discarded filters.** `/properties?page=2` dropped `q`, `status`,
   `listingType`, `propertyType` and `state`, so page 2 was page 2 of the *unfiltered*
   set while the count still described the filtered one. `/contacts` interpolated the
   search term without `encodeURIComponent`, breaking on `&` or `#`. Both rebuilt on
   `URLSearchParams`.
5. **Server validation could not reach the field that caused it.**
   `err.issues.map(i => i.message).join("; ")` threw away `issue.path`. `ActionResult`
   gained an optional `fieldErrors` map and a `failFromZod` helper; the leads, properties,
   projects and contacts actions now use it and the forms render it per input.
6. **Nothing was announced.** There was not one `role="alert"` in `components/` — a
   failed save was completely silent to a screen reader. Every bare
   `<p className="text-destructive">` in the app is now a `FormAlert`.
7. **The confirmation budget was spent backwards.** Deleting a lead (a *soft* delete)
   asked twice; `Qualify → Contact` — which makes the record permanently read-only —
   was one click, as were removing a priced unit type, deleting a property photo and
   removing someone from a project's lead pool. All four now confirm and name the
   record; the bulk-delete copy no longer claims a soft delete "cannot be undone".
8. **Arming a destructive action lost focus.** The armed state replaced the focused
   button with a different subtree, so focus fell to `<body>` and a keyboard user had to
   Tab from the top of the page to reach Confirm, with nothing announced. A shared
   `ConfirmButton` now moves focus to Confirm, exposes `role="alertdialog"`, and returns
   focus to the trigger on Escape. Verified in the browser.
9. **Modals were not modals.** `edit-lead-dialog` had `role="dialog"` and nothing else —
   Tab walked out into the table behind the backdrop and focus never returned;
   `add-form-dialog` could not be closed from the keyboard at all; `field-map-dialog` had
   no dialog role. All three now use a shared `Dialog` with a focus trap, initial focus,
   Escape, focus restore and body scroll lock. Escape on a dirty lead edit now asks
   before discarding.
10. **Holding Enter in the status cell wrote two remarks and two status changes.**
    Guarded against double submit; the input disables while pending.

### 2. High-impact workflow

11. **There was no global search.** Finding a customer by phone meant already knowing
    whether they were a *lead*, a *contact* or only reachable via an *appointment*, then
    visiting the right page — and `/pipeline`, `/dashboard`, `/inbox` and `/reports` had
    no search at all. Added a ⌘K / Ctrl-K command palette in the sidebar and the mobile
    header, searching leads, contacts, properties and projects in one query, with
    digits-only phone matching, arrow-key navigation and `aria-activedescendant`. It
    reuses the same `ownershipFilter` the list pages use, so it cannot widen what a
    person can see.
12. **No skip link.** Up to 15 sidebar links plus the help icon and account button sat
    ahead of the content in tab order on every route. Added; Playwright confirms it is
    the first tab stop and moves focus to `<main>`.
13. **Dashboard and report tiles were decorative.** "67 open leads" gave you no route to
    those 67. `StatTile` and `StatCard` gained an `href`, and the tiles, the funnel band
    stages and the report cards now link to the list that produced the number. Two tiles
    are deliberately left inert with a comment saying why (a ratio has no row set).
14. **The leads table.** Sticky header (in a bounded scroll region, since CSS cannot
    scroll one axis and leave the other visible), pinned identity column on the left and
    actions column on the right with the selected-row tint carried into both, `aria-sort`
    with a directional icon, real names for the `↻` and `D` glyph headers, an accessible
    name for the empty actions header, `aria-checked="mixed"` on the select-all box, a
    live-region selection count, six lower-value columns hidden below `lg`, `title` on
    every truncated cell, and row errors moved out of the 6 rem pinned cell.
15. **Bulk actions.** Menus gained `aria-haspopup` / `aria-expanded` / `role="listbox"`,
    outside-click and Escape close, and a real check state (the tick was permanently
    `opacity-0`). The three unlabelled icons in a row — export, delete, clear — now carry
    visible words from `sm` up.
16. **Boards.** The appointment board's move control read "Move to: *the column it is
    already in*"; it now states the current stage and offers the others. Overdue is no
    longer hue-only. The pipeline board is a labelled focusable region with real column
    headings, and every card's move control and second link name their record instead of
    ten identical "Move stage" comboboxes.
17. **Empty states could not act.** `EmptyState` always had an `action` prop and no
    caller passed one. Leads, working leads, properties, contacts and projects now
    distinguish "none yet" from "no matches" and offer the matching control.
18. **Input semantics.** `type="tel"` / `inputMode` / `autoComplete` on every phone,
    email and name field across the app — previously correct in exactly one form.
19. **Terminology.** One noun per object (*deal* for the record, *Pipeline* for the
    board, *Paperwork* for a section of the deal page), one verb for booking
    (*Schedule*), "Report" → "Reports", "Guide" → "User guide", sentence case throughout.

### 3. Visual consistency and polish

20. **Heading order.** `CardTitle` hardcoded `h3`, so every page ran h1 → h3 with no h2;
    `/reports` shipped two `h1`s. `CardTitle` now defaults to `h2` with an `as` escape
    hatch. Playwright verifies exactly one `h1` and no skipped level on 14 routes.
21. **Page titles.** 20 pages used a bare `text-xl font-semibold` `h1` while `PageTitle`
    used `font-display text-2xl font-bold`. Unified.
22. **Contrast.** `text-gray-400` on card surfaces, `text-muted-foreground/70` at 9px and
    `opacity-70` timestamps all failed 4.5:1. Replaced; nothing under 18px sits below the
    threshold now, and no size below 11px remains.
23. **Colour is never the only signal.** Zero-calls cells, zero follow-up rate, the
    no-show rate, the follow-up tile and overdue appointments each gained a word.
24. **Focus.** `ring-2 ring-ring` was invisible on the gradient primary and destructive
    buttons; every control now carries a 2px offset ring, and plain links get one too.
25. **Density.** Table rows went from a uniform `p-3` to `px-3 py-2.5 / sm:py-2` with an
    uppercase 12px header — roughly 20% more rows on a laptop at the same legibility.
26. **Reduced motion** is honoured globally.
27. **Responsive.** The tablet and mobile overflow was two implicit CSS grid tracks
    sizing to `max-content` behind a `truncate`, a six-column filter row 14px too wide,
    and an inline `<code>` list that could not break. All three fixed at source rather
    than by hiding content.

## Limitations and follow-up

1. **Two suite "failures" are test artefacts, verified by hand.** Agents *are* correctly
   redirected away from `/users`, `/templates` and `/team` (the check read the HTTP status
   of the redirect target, which is 200 for `/dashboard`). The pipeline check ran against
   the default *project* tab, which the seed leaves empty; the *resale* tab renders
   correctly named controls ("Stage for Wei Jie Nair's deal").
2. **Fonts.** Google Fonts is unreachable from both sandboxes, so every screenshot renders
   Inter and Fraunces as their fallbacks (system sans and Georgia). Before and after are
   affected equally, so the comparison holds, but it is not pixel-true to production. The
   `next/font/google` calls in `app/layout.tsx` are untouched.
3. **Not re-verified on your machine.** Your `node_modules` is a pnpm store with Windows
   symlinks that the Linux bridge cannot follow, so run
   `pnpm typecheck && pnpm test && pnpm build` locally before deploying.
4. **Team-lead role** was reviewed in code but not driven in a browser.
5. **`canEdit` for team leads** — the open item from the 3 Sep audit — was out of scope
   here and is unchanged.
6. **Saved views** are still absent; filter state is URL-driven and shareable, but there
   is no way to name and keep a combination. That is the single biggest remaining
   workflow win.
7. **Sorting** exists on three of thirteen leads columns and on no other list. Sorting by
   "quietest" (the `D` column) is the one agents would use daily.
8. **Per-route loading skeletons** — `app/(dashboard)/loading.tsx` still shows a dashboard
   shape on every list page. Cheap to add for leads, contacts and properties.
9. **`.impeccable.md`** was added at the repo root recording the design context (palette,
   Fraunces, the one-shadow budget, the funnel ramp) so future work does not drift. Delete
   it if you would rather it lived only in `DESIGNSYSTEM.md`.
